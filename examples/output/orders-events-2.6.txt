Servers (2 findings)

  ERROR    server-no-security  #/servers/broker  line 9
           The server "broker" declares no security scheme, so the document says nothing about how a client proves who it is when it connects.
           basis: "A declaration of which security mechanisms can be used with this server." (Server Object, security, https://raw.githubusercontent.com/asyncapi/spec/v2.6.0/spec/asyncapi.md)
           fix: Add the scheme (or the alternatives) that a client has to satisfy to connect, under security of the server.

  ERROR    server-plain-protocol  #/servers/broker/protocol  line 11
           The server "broker" uses the plain protocol mqtt, and the specification lists secure-mqtt for the same protocol. Messages, and the credentials that go with them, can be read and changed on the way.
           basis: "Supported protocol include, but are not limited to: amqp, amqps, http, https, ibmmq, jms, kafka, kafka-secure, anypointmq, mqtt, secure-mqtt, solace, stomp, stomps, ws, wss, mercure, googlepubsub, pulsar." (Server Object, protocol, version 2.6.0, https://raw.githubusercontent.com/asyncapi/spec/v2.6.0/spec/asyncapi.md)
           basis: "When using the clear communication profile, the MQTT protocol runs over an open network with no additional secure communication mechanisms in place." (5.4.12.1 Clear communication profile, https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html)
           fix: Use secure-mqtt (TLS) for this server, and keep mqtt for a broker on the local machine only.
